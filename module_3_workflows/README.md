## 1. Скінченний автомат (FSM) проти локального циклу (Loop)

У демонстраційних PoC розробники часто організовують роботу агентів через простий цикл `while not finished: agent.run()`. У промисловому банківському середовищі це створює критичні ризики:
* Неможливо відстежити точну позицію клієнта в багатоденному процесі.
* Будь-який рестарт процесу призводить до безповоротної втрати незавершених заявок.
* Неможливо реалізувати асинхронне очікування клієнта днями без утримання ресурсів у пам'яті.

**Рішення для Solution Architect:**
Кредитний конвеєр проектується як **скінченний автомат (Finite State Machine)**:
* Кожен стан процесу чітко типізований через модель стану (`LoanWorkflowState`).
* Переходи між вузлами визначаються умовними ребрами (Conditional Edges).
* Після кожного кроку поточний зліпок стану (Snapshot) автоматично фіксується у персистентній БД через механізм **Checkpointer**.

```
[01 intake] ──► [02 eligibility] ──► [03 kyc] ──► [04 credit_history] ──► [05 underwriter]
                                                                                  │
                   ┌──────────────────────────────────────────────────────────────┴──────────┐
                   ▼                                                                         ▼
     [06 hitl_committee (❖)]                                                      [07 contract]
     (Сіра зона: пауза до вердикту людини)                                       (Резерв ліміту в Core)
                   │                                                                         │
                   └───────────────────────────┬─────────────────────────────────────────────┘
                                               ▼
                             [08 sign_awaiting (⏸)] ◄─── Клієнт відмовився?
                             (Очікування Дія.Підпис)               │
                                       │                           ▼
                                       ▼                 [10 compensation ↺]
                             [09 disburse (✔)]           (Saga Rollback: зняття
                           (Виплата коштів клієнту)       резерву та анулювання)
```

## 2. Персистенція та Durable Waits: чому `asyncio.sleep` неприпустимий

Якщо клієнт розпочав оформлення позики вночі в Privat24, застряг на етапі фотографування паспорта і заснув — процес повинен очікувати його від 24 до 48 годин.

* **Чому `sleep` ламає продакшн:**
  Використання `asyncio.sleep(86400)` змушує контейнер тримати активний процес, виділену оперативну пам'ять та мережеві дескриптори. Під час планового оновлення версії сервісу в Kubernetes под буде вбито за сигналом `SIGKILL`, і сесія позичальника зникне назавжди.
* **Архітектурний стандарт (Durable Wait):**
  1. Вузол графа ініціює збереження стану в базу даних (Postgres / SQLite) із прив'язкою до `thread_id` (ідентифікатор заявки).
  2. Процес повністю звільняє пам'ять і повертає статус `awaiting_event`.
  3. Коли за 3 дні надходить зовнішня подія (клієнт завантажив фото або підписав договір), вебхук пробуджує систему.
  4. Будь-який вільний под у кластері зчитує останній чекпоінт за `thread_id` і продовжує виконання з наступного вузла.

## 3. Матриця порівняння State Engines (Workflow Engines)

Для вибору інструменту оркестрації у банку застосовується порівняльна матриця:

| Workflow Engine | Переваги | Обмеження | Де застосовувати у банку |
|---|---|---|---|
| **LangGraph** (Python) | Графова архітектура для AI-агентів, гнучкі цикли рефлексії, вбудовані чекпоінтери (Memory, SQLite, Postgres). | Орієнтований на Python-сервіси, складний для міжсистемної інтеграції десятків застарілих банківських систем. | **Внутрішній Workflow Engine Loan Copilot** для координації агентів Intake, KYC, CreditHistory та Underwriter. |
| **Temporal** (Distributed) | Наднадійна оркестрація, гарантія виконання коду навіть при падінні ЦОД, Event Sourcing, підтримка Go/Java/Python. | Потребує окремого інфраструктурного кластера, жорсткі вимоги до детермінізму workflow-коду. | **Глобальні фінансові транзакції** між бекенд-системами (Core Banking, платіжні шлюзи, білінг). |
| **CodeMie Workflows** | Вбудований low-code Workflow Engine платформи (Sequential mode), готові форми перегляду для операторів банку. | Обмежена гнучкість для кастомних циклічних графів. | **Швидкий випуск MVP** на корпоративній платформі EPAM. |
| **Camunda / BPMN** | Загальноприйнятий стандарт у великих банках, візуальні діаграми зрозумілі комплаєнсу та юристам. | Важкий для динамічних агентних циклів, Java-стек, високий оверхед на виклики LLM. | **Глобальний кредитно-депозитний процес банку**, який викликає Loan Copilot як зовнішній сервіс. |

> **Правило композиції:** У зрілій банківській архітектурі **Temporal або Camunda** координує наскрізний бізнес-процес між різними департаментами, а **LangGraph** працює як спеціалізований інтелектуальний мікросервіс усередині копілота.

## 4. Human-in-the-Loop (HITL): 3 моделі залучення людини

Регулятори (НБУ, ЄС) забороняють повну автономію AI при оцінці платоспроможності громадян. У Loan Copilot впроваджено 3 моделі взаємодії:

```
1. PRE-EXECUTION GATE (Гейт блокування перед дією):
   [Underwriter AI] ──► Скор у сірій зоні (550–650)? ──► ⏸ ПАУЗА: Кредитний комітет ухвалює остаточний вердикт

2. IN-FLIGHT CO-PILOT (Корекція даних на льоту):
   [OCR Tool] ──► Низька якість фото паспорта? ──► ◆ Оператор виправляє розпізнані цифри перед запуском KYC

3. POST-EXECUTION ESCALATION (Ескалація аварій):
   [External Bureau API] ──► Сервіс 503 після 3 ретраїв ──► ☠ Заявка падає в Dead-Letter чергу інженера
```

## 5. Розподілені транзакції: Saga Pattern та ідемпотентність

У мікросервісній та мультиагентній архітектурі неможливо використати класичний `Two-Phase Commit (2PC)`, оскільки взаємодія ведеться з незалежними зовнішніми сервісами (Дія.Підпис, хмарні API, картковий процесинг).

### Реалізація Saga Pattern:
* **Прямий потік дій (Forward Flow):**
  1. `contract_node`: генерація договору та **резервування кредитного ліміту** в картковому бекенді.
  2. `sign_awaiting_node`: очікування підписання позичальником.
  3. `disburse_node`: перерахування коштів.
* **Аварійний сценарій (Compensating Transaction):**
  Якщо клієнт у період роздумів натискає кнопку «Скасувати заявку» або закінчується 7-денний строк дії оферу — запускається вузол **`compensation_node`**:
  * Автоматично знімає резерв кредитного ліміту в картковій системі.
  * Анулює чернетку договору в системі електронного документообігу.
  * Відправляє повідомлення про скасування заявки в кредитне бюро.

### Захист від повторних списань (Webhook Idempotency Barrier):
Зовнішні сервіси цифрового підпису в разі мережевих затримок повторюють відправку вебхука до 3–5 разів. Для запобігання подвійній виплаті коштів впроваджено дедуплікаційний бар'єр на основі композитного хешу:
```python
key = hashlib.sha256(f"{application_id}:{event_id}".encode()).hexdigest()[:16]
if key in state["processed_events"]:
    return {"current_node": "sign_awaiting"}  # Дубль проігноровано, повертаємо 200 OK
```

## 6. Регуляторний щит: EU AI Act (High-Risk AI) та нормативи НБУ

Відповідно до Додатка III §5(b) Європейського регламенту зі штучного інтелекту (**EU AI Act**), системи оцінки кредитоспроможності фізичних осіб класифікуються як **High-Risk AI** і вимагають наявності таких обов'язкових технічних артефактів:

| Стаття закону | Вимога регулятора | Артефакт у системі Loan Copilot |
|---|---|---|
| **Art. 9** | Система управління ризиками | Реєстр ризиків моделі (Risk Register) та план моніторингу регресій. |
| **Art. 10** | Управління якістю даних | Тестування на упередженість (Bias Testing), репрезентативні вибірки. |
| **Art. 13** | Прозорість для користувачів | Обов'язкове інформування клієнта: «Вам відповідає AI-копілот». Пояснення причин відмови за конкретними пунктами політик (`[POL-LOAN-01 §4.2.1]`). |
| **Art. 14** | Людський нагляд (Human Oversight) | Інтерфейс перехоплення управління (Override UI) та кнопка екстреної зупинки для кредитного андеррайтера. |
| **Art. 15** | Надійність та кіберстійкість | Золотий набір тестових сценаріїв (Golden Set), захист від ін'єкцій у промпт. |
| **Art. 26** | Обов'язки організації | Збереження аудиторських логів (`audit.jsonl`) не менше 6 місяців для можливості судового захисту. |

**Національний оверлей (Україна):**
* **Постанова Правління НБУ № 351:** дотримання вимог до управління операційним та кредитним ризиком.
* **Закон України «Про банки і банківську діяльність» (Стаття 60):** режим банківської таємниці.
* **GDPR (Стаття 22):** абсолютне право позичальника вимагати перегляду суто автоматизованого рішення живою людиною.
